138 opcodes are installed in the dispatch table. All 138 have a located handler
and recorded evidence; **123 are exercised by at least one script in the game**,
and 15 are installed but never used by any shipped script.

`__sinit_r_script.cpp` at `0x003A6AA0` initialises `CRadiScript::pfnTable`.
Symbolic execution of its copy sequence reconstructs the BSS table at
`0x003B2D70`; the function pointer is the third word of each 12-byte entry.
Every installed entry points at a `CRadiScript::Command_XX`, and every gap
points at the shared no-op `CRadiScript::Command_xx` at `0x002E2E30`.

## Families

| Range | Area |
|---|---|
| `0x00`–`0x1F` | Script control, flags, event values, scene state, windows |
| `0x20`–`0x3F` | Characters: loading, movement, rotation, animation, expression, collision |
| `0x40`–`0x5F` | Background, map, landscape, camera, vibration |
| `0x60`–`0x7F` | 2D primitives, textures, sound, movies |
| `0x80`–`0x8F` | Vibration data, dialogue, text output, windows |
| `0xA0`–`0xD5` | Person/schedule system, battle setup, special effects |
| `0xF0`, `0xFF` | Markers and immediate return |

Two carry more weight than the rest: [`0x14`](../expression/) is the
general-purpose expression command and the single most-used opcode, and
[`0x02`](../control-flow/) is every branch and jump.

## Addresses across builds

Click an opcode for its handler address in each build. Coverage is uneven, and
the reason matters:

| Build | Handlers with a confirmed address |
|---|---:|
| Debug (`SLUS-21262` prototype) | 138 of 138 |
| ENG (USA release) | 85 of 138 |
| JPN (`SLPM-65800` release) | 85 of 138 |

The debug build ships a real linker map, so every handler is named and placed.
The release maps are **derived**: their confirmation policy omits any function
whose body does not match the reference build, so 53 handlers are simply not
pinned down there. A missing release address means "not confirmed in that map",
not "absent from that build" — the handler is installed in the dispatch table in
all three.

The 85 that are confirmed agree exactly with the addresses recovered
independently from the dispatch-table dump, in both release builds.
