## 5. ELF program header and segment memory map

<Tag kind="confirmed" /> via byte-exact parse (`e_phnum=18`, `e_phentsize=32`,
`e_phoff=0x34`), cross-checked against the boot logs and the proto memory map.
The load confirmation (`0 00100000 0008d900`) shows `0x8D900` matching `main`'s
Phdr entry 0 `p_filesz`, with an associated `memsz` of `0x000B4280` — derived
two independent ways.

### Key findings

- `main`'s own Phdr entry is `PT_NULL`; every other entry is `PT_LOAD` — this
  likely lets a loader filter on `p_type == PT_LOAD` to skip "myself."
- Only `main` has real file content (`p_offset=0x280`, `p_filesz=0x8D900`, ending
  at `0x8DB80`). **Every other segment shares that same `p_offset` with
  `p_filesz=0`** — the Phdr table records only destination and decompressed size;
  actual compressed byte boundaries come from the decompression chain
  ([§4.10](../bring-up/#410-overlay-segment-loader-hand-off-to-segment-1-step0-00)).
  The two are redundant descriptions of the same 17-segment layout.
- `p_flags=7` (RWX) for real segments; `heap` uses `p_flags=6`.
